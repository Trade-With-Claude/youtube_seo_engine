# Phase 1: Data Layer & VPH — Plan

## Acceptance Criteria

### AC1: VPH snapshots are stored
- Given a channel with fetched videos
- When the VPH polling service runs
- Then `vph_snapshots` table contains view count snapshots with timestamps for each video

### AC2: VPH is calculated and displayed
- Given videos with at least 2 snapshots
- When viewing the VPH dashboard
- Then each video shows a VPH value (views delta / hours between snapshots)

### AC3: New tables exist
- Given the app starts
- When `init_db()` runs
- Then tables `vph_snapshots`, `seo_scores`, `trend_alerts`, `ab_tests` are created

## Tasks

### Task 1: New models + VPH service
- **files:** `app/models.py`, `app/services/vph.py` (new)
- **action:** Add 4 new SQLModel tables (`VphSnapshot`, `SeoScore`, `TrendAlert`, `AbTest`) to models.py. Create `vph.py` service that fetches current view counts for all tracked videos using `youtube_api.py` and stores snapshots. Add VPH calculation function (delta views / delta hours between latest 2 snapshots).
- **verify:** `python -c "from app.models import VphSnapshot, SeoScore, TrendAlert, AbTest; print('OK')"` and `python -c "from app.services.vph import poll_vph, calculate_vph; print('OK')"`
- **done:** true

### Task 2: VPH router + dashboard UI
- **files:** `app/routers/vph.py` (new), `app/main.py`, `app/templates/vph.html` (new), `app/templates/base.html`
- **action:** Create VPH router with endpoints: POST `/vph/poll` (trigger polling), GET `/vph` (show VPH dashboard). Add VPH page template with sortable table showing video title, current views, VPH, last polled time. Add nav link in base.html. Register router in main.py.
- **verify:** Run app, navigate to `/vph`, trigger a poll, see VPH values appear.
- **done:** true

## Boundaries
- **DO NOT CHANGE:** `app/services/youtube_api.py` (reuse existing `get_youtube_service()`), OAuth flow, existing templates (except adding nav link to base.html)
- **OUT OF SCOPE:** Automated scheduling of VPH polls (manual trigger only for now), SEO scoring logic (phase 2), trend alert logic (phase 4)
