# Phase 6: Polish — Plan

## Acceptance Criteria

**AC1:** Given I click any API action (score keywords, discover competitors), when it takes a while, then I see a loading state — not a frozen page.

**AC2:** Given an API call fails (bad key, quota exceeded, network error), then I see a clear error message — not a 500 crash.

**AC3:** Given I'm a new user cloning the repo, when I follow the setup page, then I can get the app running and add my channel in under 5 minutes.

## Tasks

### Task 1: Error handling + loading states
- **files**: `app/templates/base.html`, `app/routers/competitors.py`, `app/routers/trends.py`, `app/routers/metadata.py`, `app/services/scoring.py`, `app/services/competitors.py`
- **action**: Add try/except around all YouTube API calls in routers so errors redirect with a clear message instead of crashing. Add a simple CSS loading indicator on buttons that submit forms (disable button + "Working..." text via JS).
- **verify**: Kill the API key in .env → click "Score Keywords" → see a friendly error message, not a 500. Restore key → click → see loading state on button.
- **done**: true

### Task 2: Onboarding polish + setup guide update
- **files**: `app/templates/setup.html`, `app/templates/dashboard.html`, `.env.example`, `requirements.txt`
- **action**: Update the setup page with clear step-by-step instructions. Add empty-state guidance on dashboard. Ensure requirements.txt is complete and .env.example has all needed vars documented.
- **verify**: `pip install -r requirements.txt` installs everything. Setup page has clear steps. Dashboard shows guidance when no channel exists.
- **done**: true

## Boundaries
- **DO NOT CHANGE:** `app/database.py`, `app/models.py`, `app/services/reports.py`
- **OUT OF SCOPE:** Deployment, Docker, CI/CD, multi-user auth
